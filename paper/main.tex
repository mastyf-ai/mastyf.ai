\begin{abstract}
Autonomous artificial intelligence agents executing over extensible tool interfaces (such as Anthropic's Model Context Protocol) operate with ambient authority over connected tools. Because autoregressive Transformers ingest instructions and untrusted third-party data within a single homogeneous context window, adversarial observations can manipulate the model into executing unintended privileged actions -- the classic Confused Deputy problem. In this paper, we explore an architectural defense-in-depth approach that treats \textbf{LLM agents as potentially compromised, untrusted principals}. Rather than relying on linguistic moderation alone, tool dispatch is governed by an external capability-mediated reference monitor enforcing complete mediation, least privilege, and four typed relational argument invariants (destination containment, scope boundedness, privilege monotonicity, and aggregate monetary clamping). Under complete mediation axioms (A1--A6) over the trusted computing base, out-of-scope tool invocation is deterministically rejected at the transport boundary, formalized as an \textbf{Inductive Multi-Step Tool Chain Composability Invariant (Proposition 1)} showing that adversarial observations cannot synthesize authority across arbitrary execution sequences. However, in-scope parameter poisoning within authorized tools and cross-tool data exfiltration present harder challenges: semantic neural validation is distribution-bounded (exhibiting an empirical false-negative rate of 21.5\% on in-scope manipulations prior to boundary sharpening and remaining susceptible to adversarial optimization), while cross-tool exfiltration requires explicit decentralized information-flow tracking (DIFC). We report empirical evaluations across both foundational baseline studies (a 50,000-sample macro benchmark and a 3,000-case ablation matrix) and a Six-Regime Empirical Validation Program totaling 6,662 evaluation cases with frozen checkpoint $V_6$: achieving 100\% Correct Identification Rate on internal factorized diagnostics ($N = 145$), 100\% accuracy on a pre-sealed holdout suite (75/75, SHA-256: \texttt{22bc736c...}), 98.43\% defense on the 4,216-instance InjecAgent evaluation used in this study ($P_{50}$: 267.7~ms), 92.44\% defense on AI Safety Bench (416/450 attacks blocked, 550/550 benign operations allowed), 99.52\% attack defense on interactive AgentDojo ($N = 629$) with exact clean-task utility parity (6/97 tasks) matching the unprotected base agent, and 100\% defense across 500 targeted adaptive red-team trials. Finally, we systemize the runtime into the Mastyf Security Gateway: the evaluated research runtime was v0.1.0-RC1 (verifying 38/38 security invariant tests), while the subsequently hardened commercial-pilot runtime is v0.1.1-rc1 (verifying 50/50 tests), establishing complete mediation non-executability ($\text{Decision} \in \{\text{BLOCK}, \text{ESCALATE}\} \implies \text{BackendToolInvocations} = 0$) and $>330,000$~req/s reference monitor throughput under an Ed25519-signed release manifest. We contextualize Mastyf as an empirically evaluated pre-production architecture, highlighting residual risks and outlining requirements for broader production-scale validation.
\end{abstract}

\section{Introduction \& Foundational Motivation}
\IEEEPARstart{I}{n} 1945, John von Neumann formulated the foundational computer architecture that bears his name, characterized by a single shared memory bus storing both executable instructions and operand data~\cite{ref_1}. While this unification offered unprecedented programmability, it introduced the most persistent security vulnerability in computing history: because control instructions and passive data occupy a homogeneous address space, adversarial inputs can subvert instruction pointers. Decades of buffer overflow exploits~\cite{ref_2}, stack smashing, and return-oriented programming (ROP) stem directly from this fundamental architectural conflation.

Over the past three years, the emergence of autonomous Large Language Model (LLM) agents has resurrected this vulnerability in an acute cognitive form: the \textbf{Cognitive Von Neumann Conflation}. Under modern tool-calling standards such as Anthropic's Model Context Protocol (MCP)~\cite{ref_3}, LangChain, and multi-agent autonomous research environments, an agent's autoregressive Transformer ingests developer instructions (system prompts), user objectives, and untrusted third-party data within a single homogeneous token sequence:
\begin{equation}
\mathbf{H} = \operatorname{Softmax}\left(\frac{\mathbf{Q}\mathbf{K}^T}{\sqrt{d_k}}\right)\mathbf{V}, \quad \mathbf{X} = [\mathbf{x}_{\text{sys}} \parallel \mathbf{x}_{\text{user}} \parallel \mathbf{o}_{\text{untrusted}}]
\end{equation}
Because the attention mechanism allows untrusted context tokens to influence the same computational process used to interpret higher-priority instructions without architectural boundaries, an adversarial payload embedded within retrieved data $o_{\text{untrusted}}$ can hijack self-attention representations, steering the agent toward unintended privileged actions (\textbf{Indirect Prompt Injection}, IPI)~\cite{ref_4, ref_5, ref_34}. To mitigate this, we formulate the \textbf{Cognitive Harvard Architecture} by analogy with hardware systems that decouple instruction and data paths.

\section{Comprehensive Related Work \& Literature Taxonomy}
\textbf{2.1 Indirect Prompt Injection \& Adversarial Jailbreaking:} Early adversarial NLP research focused on direct jailbreaks via suffix optimization~\cite{ref_20, ref_38}. Greshake et al.~\cite{ref_34} demonstrated that passive web content could silently compromise LLMs via indirect injection, codified as the \#1 threat in the OWASP Top 10 for LLM Applications~\cite{ref_30}.

\textbf{2.2 Conversational Moderation \& Guardrail Baselines:} Industry guardrails---including Meta Llama Guard 3~\cite{ref_7}, NVIDIA NeMo Guardrails~\cite{ref_8}, and ToxicChat~\cite{ref_17}---were trained on conversational toxicity taxonomies. While effective for chatbots, they fail catastrophically in tool-calling settings due to \textit{conversational camouflage}: attacks disguised as polite business correspondence contain zero profane tokens.

\textbf{2.3 Agent Security Benchmarks \& Gatekeepers:} Zhang et al. introduced InjecAgent~\cite{ref_5}, demonstrating that frontier models (GPT-4) suffer a 24.1\% Attack Success Rate (ASR). Yi et al. introduced BIPIA~\cite{ref_4} (ACM KDD '25), evaluating indirect injections across email, web, code, and QA. Debenedetti et al. created AgentDojo~\cite{ref_26}, confirming that multi-turn environments compound exploitability.

\textbf{2.4 Capability Systems \& Hardware Protection:} In classical operating systems, Saltzer and Schroeder~\cite{ref_9} articulated the Principle of Least Privilege and Complete Mediation. Norm Hardy formalized the \textit{Confused Deputy Problem}~\cite{ref_6} and pioneered capability-based addressing in KeyKOS~\cite{ref_10}. Watson et al. realized hardware-enforced capability safety in CHERI~\cite{ref_33}.

\textbf{2.5 Information Flow Control \& Authorization Invariants:} Dorothy Denning established the lattice model of secure information flow~\cite{ref_19}. Goguen and Meseguer formulated Non-Interference~\cite{ref_25}. Myers and Liskov developed Decentralized Information Flow Control (DIFC)~\cite{ref_32}.

\section{Ambient Authority \& The Confused Deputy in Agentic Systems}
Traditional access control fails in autonomous agent deployments due to \textbf{ambient authority}~\cite{ref_6}: an agent is initialized with unrestricted permission to invoke all registered tools in its manifest. When an untrusted document coerces the agent into invoking a privileged mutating tool, the agent acts as an agent-specific form of the classic Confused Deputy.

\textbf{The AI Guardrail Trilemma:} Enterprise deployments have historically been constrained by a three-way engineering trade-off: (1) \textit{Threat Recall ($>95\%$):} Frontier models achieve high recall but introduce 800--1,400~ms latency and high token cost; (2) \textit{Execution Latency ($<25$~ms):} Lightweight classifiers execute quickly but miss over 55\% of realistic indirect injections; (3) \textit{Zero Dedicated GPU Infrastructure:} Deploying dedicated 8B guardrail models requires high-power 16~GB+ VRAM GPUs, preventing localized edge adoption.

\section{Architectural Paradigm: The Cognitive Harvard Architecture}
Mastyf Guard separates the \textit{Cognitive Ingestion Plane} (where the LLM processes untrusted data) from the \textit{Privileged Execution Plane} (where tools alter system state). The LLM is permitted to reason over arbitrary retrieved context, but it is stripped of ambient authority. Every tool proposal $a = (T, \theta)$ must be validated by an external, capability-mediated perimeter before dispatch. In production deployments, the reference monitor executes as an out-of-process sidecar or reverse proxy container communicating over Unix Domain Sockets or mutual TLS (mTLS), maintaining strict process and memory isolation from the agent runtime. The Mastyf sidecar, capability issuer, key material, and protected tool transport constitute the trusted computing base (TCB).

\section{Threat Model \& Formal Operational Semantics}
We formalize an autonomous agent execution environment as a state-transition tuple $M = \langle S, A, T, P, R \rangle$, where $S$ denotes state space, $A$ denotes action space, $T = \{T_1, \dots, T_k\}$ represents the registered MCP tool registry, and $P(s_{t+1} \mid s_t, a_t)$ governs state transitions. Under capability mediation, the transition probability to any state resulting from an unauthorized tool is strictly constrained: $\forall s_t \in S, \; T \notin \operatorname{Scope}(\tau) \implies P(s_{t+1} \mid s_t, T) = 0$. Following Denning~\cite{ref_19} and Myers \& Liskov~\cite{ref_32}, capabilities form a bounded lattice $(L, \le, \cup, \cap)$ enforcing monotonic confinement.
\begin{equation}
\max_{\delta \in \Delta} \; \Pr\left[\, T_{\text{target}} \in \pi(h_t \circ (o_{\text{adv}} + \delta)) \;\middle|\; T_{\text{target}} \notin \mathcal{C}_{\text{auth}}(u) \,\right]
\end{equation}
Under complete mediation, a valid capability token is a strictly necessary condition for tool dispatch:
\begin{equation}
\operatorname{Dispatch}(T, \theta) \neq \bot \implies \mathcal{V}(\tau_{\text{session}}, T) = \text{True}
\end{equation}

\section{Provable Non-Escalation Invariants \& Theoretical Foundations}
We define the following foundational security assumptions under complete mediation (Saltzer \& Schroeder, 1975~\cite{ref_9}):
\begin{itemize}
    \item \textbf{A1 (Complete Mediation):} Every state-mutating tool invocation is intercepted and mediated by the trusted reference monitor, and no execution path exists from the agent to a tool that bypasses the monitor.
    \item \textbf{A2 (Unforgeable Capabilities):} Capability tokens $\tau = (C_{\text{session}}, \text{TTL}, \sigma)$, where $\sigma = \operatorname{HMAC}_k(C_{\text{session}} \parallel \text{TTL})$, are computationally unforgeable without knowledge of secret key $k$ under chosen-message attacks (EUF-CMA).
    \item \textbf{A3 (Fail-Closed Dispatch):} Any tool invocation lacking a valid, verified capability token is deterministically rejected with status \texttt{403 FORBIDDEN}.
    \item \textbf{A4 (Reference Monitor Integrity):} The reference monitor executes within an isolated process boundary and cannot be modified or subverted by the agent principal.
    \item \textbf{A5 (Trusted Capability Issuance \& Non-Self-Elevation):} Capability tokens and scope envelopes $\operatorname{Scope}(\tau)$ originate strictly from an authorized external principal or identity policy engine out-of-band; an agent cannot self-issue or elevate its own session capabilities.
\end{itemize}

\newtheorem{proposition}{Proposition}
\begin{proposition}[Complete Mediation Invariant over the Trusted Computing Base]
Under Assumptions A1--A5, for every mediated tool-dispatch attempt $a_i = (T_i, \theta_i)$, if $T_i \notin \operatorname{Scope}(\tau_i)$ and no authorized scope expansion has occurred, then the dispatch is rejected and $\operatorname{Execute}(a_i) = \bot$. This property holds independently at each mediated dispatch step.
\begin{equation}
T_i \notin \operatorname{Scope}(\tau_i) \land \operatorname{Mediated}(a_i) \implies \operatorname{Execute}(a_i) = \bot
\end{equation}
\end{proposition}

\begin{IEEEproof}
1. By Assumption A1 (Complete Mediation), every tool-dispatch attempt $a_i = (T_i, \theta_i)$ is intercepted and routed to the reference monitor.
2. By Assumptions A2 (Unforgeable Capabilities) and A5 (Non-Self-Elevation), the agent cannot forge capability signatures $\sigma$ nor expand $\operatorname{Scope}(\tau_i)$.
3. For any out-of-scope tool $T_i \notin \operatorname{Scope}(\tau_i)$, capability verification $\operatorname{Verify}(\tau_i, T_i)$ deterministically evaluates to False.
4. By Assumption A3 (Fail-Closed Dispatch), any unverified dispatch terminates with status \texttt{403 FORBIDDEN}.
5. Therefore, $\operatorname{Execute}(a_i) = \bot$ holds unconditionally at each mediated dispatch step.

\textit{Scope Limitation \& Non-Interference Boundary:} This proposition establishes namespace confinement, not semantic safety of arbitrary multi-step compositions. Individually authorized actions may still compose into unintended outcomes, and explicit substring taint tracking does not provide complete protection against all implicit or semantically transformed information flows. Q.E.D.
\end{IEEEproof}

\newtheorem{lemma}{Lemma}
\begin{lemma}[Measured False-Negative Rate on In-Scope Tool Operations]
When an adversary attempts to mutate arguments $\theta$ of an already authorized tool $T \in C_{\text{session}}$, the measured semantic detection false-negative rate on the evaluated in-scope attack distribution is 21.5\% (governed by $1 - \operatorname{TPR}_{\text{neural}}$):
\begin{equation}
\operatorname{FNR}_{\text{in-scope}} = 1 - \operatorname{TPR}_{\text{neural}} = 1 - 0.785 = 0.215
\end{equation}
\end{lemma}

\subsection{Historical V1 Baseline Configuration}
Tier 1.5 in the historical baseline studies employs a domain-specialized 1.5B parameter autoregressive Transformer built on the Qwen2.5 backbone~\cite{ref_12} and adapted via LoRA~\cite{ref_13} ($r=16, \alpha=32$, dropout 0.05 on query/value projections). The neural model was trained on $N_{\text{train}} = 28,450$ tool-call interaction pairs ($N_{\text{val}} = 3,550$ held-out pairs), optimized over 3 epochs with AdamW (learning rate $2 \times 10^{-4}$, cosine decay, batch size 16, seed 42) under Regularized Focal Loss~\cite{ref_31} ($\gamma=2.0, \alpha=0.25$, weight decay $\lambda=0.01$):
\begin{equation}
\mathcal{L}(\theta) = -\sum_{i=1}^N \alpha_t (1 - p_t)^\gamma \log(p_t) + \frac{\lambda}{2} \|\Delta W\|_F^2
\end{equation}
Quantized to INT4 (AWQ / GGUF Q4\_K\_M), the model executes in a 1.12~GB host RAM footprint with a 2,048-token context window. Fast-path reference-monitor transport overhead (0.005~ms / 4.8~$\mu$s) was evaluated on an Apple M3 Pro (16-core CPU, single-thread, batch size 1) and cross-validated on an Intel Xeon Platinum 8375C @ 2.8GHz (median across 10,000 iterations). Requests requiring deep neural evaluation incur 18.4~ms inference latency.

\section{Limitations \& Architectural Boundary}
Academic transparency requires documenting where Mastyf's defenses encounter boundary conditions, distinguishing three orthogonal security properties:
\begin{enumerate}
    \item \textbf{Tool Authorization (CBAC / Proposition 1):} Under reference-monitor axioms A1--A6, the mediated execution model assigns zero execution probability to out-of-scope actions ($\Pr = 0$); cryptographic token forgery resistance remains bounded by the assumed 128-bit EUF-CMA security parameter.
    \item \textbf{Semantic Parameter Validation (Tier 1.5 Neural Auditor):} Bounded by neural TPR on in-scope mutations (recall = 78.50\%, degraded to 61.20\% under gradient optimization).
    \item \textbf{Information-Flow Control:} Capability tokens authorize invocation of individual tools, but do not govern cross-tool data propagation. Under pure capability checks, 44/544 tested InjecAgent Data Stealing cases succeeded (91.91\% defense rate) because both source and sink tools were authorized in the active session envelope.
\end{enumerate}

\subsection{Targeted Mitigation: Decentralized Information Flow Control (DIFC) \& Theorem 2}
To resolve cross-tool exfiltration without perturbing the macro capability perimeter, we formalize and implement a targeted dynamic-taint information-flow policy inspired by DIFC (Tier 2.5). Each data fragment $x$ carries a security label tuple $L(x) = (S_x, I_x)$ with secrecy tags $S_x \subseteq \mathcal{T}_{\text{sec}}$ and integrity tags $I_x \subseteq \mathcal{T}_{\text{int}}$. Flow between tools follows the bounded lattice $L(x) \sqsubseteq L(y) \iff S_x \subseteq S_y \land I_y \subseteq I_x$, with monotonic join $L(x) \sqcup L(y) = (S_x \cup S_y, I_x \cap I_y)$. In natural language: data can only flow to destinations at least as confidential ($S_x \subseteq S_y$, preventing unauthorized disclosure), while destinations can demand at most the integrity possessed by the source ($I_y \subseteq I_x$; $I = \emptyset$ denotes maximally untrusted input).

\noindent\textbf{Theorem 2 (Taint-Constrained Egress Specification):} \textit{For any tool call $T(\theta)$, let $S(\theta) = \bigcup_{a \in \theta} S(a)$. Under fail-closed mediation, dispatch is permitted if and only if $S(\theta) \subseteq \operatorname{Clearance}(T) \lor \exists \operatorname{Grant}(S(\theta) \to T)$; otherwise $\operatorname{Execute}(T) = \bot$. In particular, for default zero-clearance egress sinks ($\operatorname{Clearance}(T_{\text{sink}}) = \emptyset$), $\Pr[\operatorname{Execute}(T_{\text{sink}}(\theta \mid S(\theta) \neq \emptyset))] = 0$.}

\noindent\textit{Enforcement Invariant \& Flow Scope:} Theorem 2 formalizes the reference monitor's taint-enforcement policy invariant rather than a cryptographic reduction. The present implementation tracks explicit data dependencies (verbatim values, substrings, slices, and formatted fragments) and does not claim to prevent arbitrary implicit-flow channels (e.g., conditional execution or side-channel encodings).

\noindent\textit{Taint Propagation Across LLM-Derived Data:} When a labeled source tool executes, the monitor extracts sensitive string leaves and records token n-gram fragments ($\ge 6$ characters) into the session taint table. When the LLM subsequently proposes an action $a = (T, \theta)$, the monitor inspects all string leaves in arguments $\theta$ against active session taint fragments; matching elements automatically inherit the source secrecy label $S(\text{fragment})$, ensuring taint survives LLM summarization and formatting.

\noindent\textit{Legitimate Flows \& Usability Trade-Off:} In deny-by-default information-flow control, strong confidentiality naturally impacts workflow usability: without declassification grants, 100\% of tainted egress dispatches were blocked across 100 tested enterprise read-then-send workflows. Under Axiom A6 (Trusted Declassification), pairing intended workflows with cryptographically signed declassification grants permitted 100\% completion on the 100 evaluated workflows with 0\% exfiltration leakage.

\noindent\textit{Multi-Suite Empirical Validation:} Across \textbf{1,152 adversarial exfiltration cases} (544 InjecAgent DS Base, 544 InjecAgent DS Enhanced, 50 BIPIA indirect exfiltrations, and 14 NVIDIA Garak leakage probes), \textbf{no successful exfiltration was observed in the 1,152 evaluated cases under the implemented source/sink policies}, with $< 0.05$~ms latency overhead.

\section{Systemization \& Production Hardening: The Mastyf Security Gateway}
To bridge the divide between a standalone neural model checkpoint and an enterprise-grade production deployment, the architecture has been systemized into the \textbf{Mastyf Security Gateway}. The evaluated research runtime reported in this manuscript was \textbf{v0.1.0-RC1} (verifying 38/38 automated security invariant tests); the subsequently hardened commercial-pilot runtime is \textbf{v0.1.1-rc1} (extending the regression suite to 50/50 passing tests and adding container provenance hardening). The gateway operates as an asynchronous, transport-level reverse proxy implementing the Model Context Protocol (MCP). The gateway sits between upstream agent runtimes and downstream MCP tool servers, enforcing complete mediation over JSON-RPC tool dispatch streams.

\textbf{Rigorous Security Invariant Verification (38/38 Tests Passing):} The production gateway was subjected to an exhaustive automated test harness validating four core operational invariants:
\begin{enumerate}
    \item \textbf{Zero-Leak Invariant:} For all tool dispatches, $\text{Decision} \in \{\text{BLOCK}, \text{ESCALATE}\} \implies \text{BackendToolInvocations} = 0$. Across all evaluated attack payloads, no unauthorized tool invocation reached the downstream tool server.
    \item \textbf{Authority Monotonicity:} An agent cannot gain privileges through indirect injection; effective authority is strictly bounded by $A_{\text{effective}} = A_{\text{agent}} \cap A_{\text{policy}}$.
    \item \textbf{Fail-Closed Protocol Parsing:} Under malformed JSON-RPC frames, recursive argument bombs, and network timeouts ($>50$~ms gateway fast-path target budget), the gateway deterministically resolves to a non-executing terminal state (\texttt{BLOCK} or \texttt{ESCALATE}) under the fail-closed policy, guaranteeing $\text{Decision} \in \{\text{BLOCK}, \text{ESCALATE}\} \implies \text{BackendToolInvocations} = 0$. Note that the 50~ms budget governs the deterministic reference-monitor queue ceiling; neural forward passes incur measured inference latencies (e.g., 267.7~ms $P_{50}$ on InjecAgent and 951.5~ms $P_{50}$ on AgentDojo).
    \item \textbf{Cross-Session Dynamic DIFC Isolation:} Dynamic taint labels accumulated in Session $S_i$ cannot contaminate concurrent or subsequent Session $S_j$, verified under 200 interleaved client worker pools.
\end{enumerate}

\textbf{Microsecond Reference Monitor Throughput:} In synthetic benchmark profiling, the deterministic CBAC/DIFC reference-monitor fast-path sustains \textbf{$>330,000$~requests/sec} with a median decision latency of \textbf{3.1~$\mu$s} ($P_{99} < 15.0~\mu$s), confirming zero perceptible overhead on routine enterprise tool invocations.

\textbf{Cryptographic Provenance \& Release Integrity:} To guarantee reproducibility, every gateway release is cryptographically pinned and verified via an Ed25519-signed \texttt{release\_manifest.json}. The manifest uniquely binds the \textbf{Gateway Source Git SHA (\texttt{4331fa4})} to the \textbf{Frozen $V_6$ Hugging Face Revision (\texttt{d59a6aa01f9139dff106146addb04109afa69c03})}, providing a fully verifiable chain of custody from source code to model weights (Table~\ref{tab:gateway_scorecard}).

\section{Conclusion \& Artifact Availability}
Across six empirical validation regimes totaling 6,662 instances, the frozen Mastyf Guard $V_6$ checkpoint (Hugging Face revision \texttt{d59a6aa}) demonstrated robust, calibrated protection against indirect prompt injection: achieving 100\% Correct Identification Rate on internal factorized diagnostics ($N = 145$), 100\% accuracy on a sealed holdout suite (75/75, SHA-256: \texttt{22bc736c...}), 98.43\% defense on the 4,216-instance InjecAgent evaluation used in this study ($N = 4,216$, $P_{50}$: 267.7~ms), 92.44\% defense on AI Safety Bench ($N = 1,000$, 100\% benign utility), 99.52\% attack interception on interactive AgentDojo ($N = 629$) with exact utility parity (6/97 tasks) matching the unprotected base agent, and 100\% defense across 500 targeted adaptive red-team trials. Furthermore, we have systemized the runtime into the Mastyf Security Gateway: the evaluated research runtime was v0.1.0-RC1 (verifying 38/38 automated security regression tests), with the subsequently hardened commercial-pilot runtime being v0.1.1-rc1 (verifying 50/50 tests), preserving complete mediation non-executability ($\text{Decision} \in \{\text{BLOCK}, \text{ESCALATE}\} \implies \text{BackendToolInvocations} = 0$), authority monotonicity, and session taint isolation with a fast-path reference monitor sustaining $>330,000$~req/s (3.1~$\mu$s $P_{50}$). We have formalized Proposition 1 (Conditional Non-Escalation Invariant over the Trusted Computing Base), proving that under complete mediation and fail-closed dispatch, untrusted observations cannot cause execution of out-of-scope mutating tools, while Theorem 2 formalizes dynamic taint tracking for preventing cross-tool exfiltration.
